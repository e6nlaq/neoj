# ランダムテストケースを生成する

`neoj generate` は2つのプログラムを組み合わせて、ランダムなテストケースを作ります。

- **ジェネレータ**(`generate.gen`)がテストケースの入力を出力します。
- **素朴な解法**(`generate.naive`)がその入力から期待する出力を作ります。

どちらも解法と同じ形式でビルドされ、言語は `[languages.<key>]` から判別されるため、C++のジェネレータとPythonの素朴な解法を自由に組み合わせられます。

## ツールを設定する

2つのソースを `neoj.toml` に追加します。

```toml
[generate]
gen = "judge/gen.cpp"
naive = "judge/naive.cpp"
```

ジェネレータは**最初の引数にケース番号を受け取って**実行されます。これにより、悪いケースを再現できます。`random-7` が壊れていたら、`judge/gen.cpp 7` が同じケースをもう一度作ります。典型的なジェネレータは、シードを読み込み、乱数エンジンを初期化し、入力を1つ出力します。

```cpp
// judge/gen.cpp
#include <iostream>
#include <random>

int main(int argc, char* argv[]) {
    std::mt19937 rng(argc > 1 ? std::stoul(argv[1]) : 0);
    std::cout << rng() % 100 << " " << rng() % 100 << "\\n";
}
```

素朴な解法は標準入力から入力を読み、期待する出力を出力します。意図的に遅くても単純でもかまいません。求められるのは速度ではなく正しさです。

## ケースを作る

```text
$ neoj generate
✔ Created 2 test case(s): random-1, random-2.
```

実行のたびに、テストケースディレクトリの中で空いている次の番号を使うため、既存のケースを置き換えません。ケースは既定で並列に生成され、進捗バーが完了した数を示します。

- `-c 20`(`--count`)で、1回の実行が作るケース数を増やせます。既定は `generate.count` が決めます。
- `-i`(`--input`)は `.in` ファイルだけを作り、素朴な解法を飛ばします。出力にかかる時間を払う前に、遅い解法をストレステストするときに使います。
- `-J 4`(`--jobs`)で同時に生成するケースの数に上限を付けられます。`--no-parallel` は1つずつ生成します。

ファイル名は `generate.filename`(既定は `random-{}`)、ディレクトリは `testcase.folder` から決まります。新しいケースで解法を試すには、そのあとで `neoj test` を実行します。

## 失敗と中断

ジェネレータの標準出力はそのまま素朴な解法にパイプされ、各ケースの2つの部分は、両方が完成するまでメモリに保持され、そのあと一気に書き込まれます。このため:

- Ctrl-C は実行中のプログラムを止め、書き込み中だったケースを削除します。すでに完成したケースはディスクに残ります。
- ツールが0以外の終了状態で終わる、`generate.timeout` 秒でタイムアウトする、出力の上限を超えて書き込む、のいずれかが起きると、ケース名を示しツールのstderrを見せるエラーで実行全体が止まります。完成したケースはディスクに残ります。

タイムアウトはたいてい、ジェネレータが作る入力に対して素朴な解法が遅すぎることを意味します。ジェネレータの制約を調整するか、`generate.timeout` を上げてください。

すべてのオプションは [CLIリファレンス](../reference/cli.md#generate) と[設定リファレンス](../reference/configuration.md#generategen)にあります。
