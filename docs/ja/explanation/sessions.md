# セッションと認証情報の保護

`neoj` は認証情報をプラットフォームごとに保存します。AtCoderはブラウザのセッションcookieを、yukicoderはブラウザのデバイスフローによる提出専用のCLIトークンかアカウントのAPIキーを使います。この仕組みでCLIは単純なまま保たれ、パスワードの保存を避けられます。その一方で、各認証情報の力は、プラットフォームが与えるものとちょうど同じになります。

## 保存前に検証する

貼り付けられたcookieやAPIキーは、ディスクに書き込む前にプラットフォームに照らして確認されます。打ち間違いや有効期限が切れたyukicoderトークンは、後で分かりにくいエラーを生む代わりに、すぐに失敗します。yukicoderのCLIトークンは有効期限とともに保存され、その時刻を過ぎるとログアウト済みとして扱われます。

## 被害の広がりを小さく保つ

認証情報は、ユーザーごとのデータディレクトリの中の1つのファイルに置かれ、プロジェクトのディレクトリには決して置かれません。

- POSIX のシステムでは、ディレクトリは `0700`、ファイルは `0600` で作られます。
- 書き込みは一時ファイルと名前の変更で行われるため、途中で終了した実行が保存済みセッションを切り詰めることはありません。
- 最後のプラットフォームからログアウトすると、空のファイルを残す代わりに、ファイルが削除されます。

ファイルは単純なJSONのため、ユーザーとして動くものであれば何でも読めます。`neoj` は暗号化ではなくオペレーティングシステムのファイル権限に頼っており、ログやエラーメッセージにcookieを出力することは決してありません。

## 保護できないこと

- AtCoderのセッションcookieは、有効期限が切れるまでアカウントへの完全なアクセスを許します。コマンドごとの範囲の制限はありません。yukicoderのAPIキーも広いアクセスを持ちます。yukicoderのCLIトークンは提出と現在のユーザーの確認に限られ、24時間で有効期限が切れますが、有効な間は秘密情報であることに変わりありません。
- ユーザーとして動くマルウェアや別のプロセスは、ファイルを読めます。
- リポジトリ、Issue、チャットにコピーされた認証情報は、別の場所でログアウトしたあとでも、漏れたままです。

どの認証情報もパスワードとして扱い、必要なくなったらログアウトしてください。
