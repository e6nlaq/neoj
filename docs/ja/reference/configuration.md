# 設定リファレンス

`neoj` は `~/.neoj.toml` と最も近いプロジェクトの `neoj.toml` を読み、結合し、結果を厳格なスキーマで検証します。未知のキーはエラーです。結合はテーブル単位で行われ、プロジェクトファイルで設定されたキーが、グローバルファイルの同じキーを置き換え、その他のキーは保たれます。

各キーは下の一覧のスコープにしか設定できません。グローバルファイルに `src` や `[template]` のキーを設定するとエラーになります。

ファイルが公開中のスキーマを指しているとき、エディタはこれらのキーを補完できます。[エディタ補完を設定する](../how-to/setup-editor-completions.md)を参照してください。

## キー

### `src`

| 型          | 既定値 | スコープ     |
| ----------- | ------ | ------------ |
| string path | なし   | プロジェクト |

解法テンプレートのコピー先ディレクトリ。プロジェクトのルートから解決されます。`template.enable = true` のときに必須で、プロジェクトの中に留まること、シンボリックリンクを通らないこと、`.git` と `.neoj` を指さないこと、`template.folder` と重ならないことが必要です。

### `alias.<name>`

| 型          | 既定値 | スコープ                     |
| ----------- | ------ | ---------------------------- |
| string path | なし   | グローバルまたはプロジェクト |

ソースパスの代わりに `neoj test` が受け付ける、追加の名前です。

```toml
[alias]
main = "src/main.cpp"
old = "archive/2019/a.cpp"
```

この設定のあと、`neoj test main` は `src/main.cpp` をビルドします。各エイリアスは、1つの名前を1つのパスに対応付けます。

- 対象は常にプロジェクトのルートから解決されるため、エイリアスはどのサブディレクトリからでも使えます。
- 対象は実在する通常のファイルで、プロジェクトの中になければなりません。エイリアスが別のエイリアスを指すことはできません。
- 同じ名前のファイルが存在してもエイリアスが優先されます。そのファイルをテストするときは `./main` を使います。
- エイリアスとの照合対象は、`neoj test` の位置引数だけです。`test.source` は常にそのままのパスとして扱われます。
- 名前は空でないこと、`.`、`..`、`/` や `\` を含まないことが必要です。
- 照合は完全一致で、大文字小文字を区別します。グローバルとプロジェクトの両方のファイルに同じ名前があるときは、プロジェクトの値に解決されます。

### `login.open_browser`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

yukicoderのCLIトークンのデバイスフローで、ブラウザを自動で開きます。検証のURLとコードは常に表示されるため、`false` のときや、ブラウザを開けないとき(SSH経由など)でもログインは動きます。

### `login.auto_login`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

`neoj submit` が有効なセッションを見つけられないとき、プラットフォームのログインの流れを自動で始めます。流れを中断すると `0` で終わります。`false` のときは、コマンドが代わりに失敗し、`neoj login <platform>` の実行を促します。

### `testcase.folder`

| 型          | 既定値 | スコープ                     |
| ----------- | ------ | ---------------------------- |
| string path | `test` | グローバルまたはプロジェクト |

ダウンロードしたサンプルと手作りのテストケースを受け取るディレクトリ。パスはプロジェクトのルート(最も近い `neoj.toml` があるディレクトリ)から解決されます。プロジェクトの中に留まること、シンボリックリンクを通らないこと、`.git` と `.neoj` を指さないことが必要です。`src` と重なってはいけません。どちらかのディレクトリがもう一方を含む形も禁止です。

各ダウンロードはディレクトリ全体を置き換えるため、手で置いたファイルは削除されます。

### `testcase.filename`

| 型     | 既定値      | スコープ                     |
| ------ | ----------- | ---------------------------- |
| string | `sample-{}` | グローバルまたはプロジェクト |

各サンプルファイルのベース名。`{}` をちょうど1つ含み、そこが1始まりのサンプル番号に置き換わること、そして有効なファイル名であることが必要です。`<>:"/\|?*` の文字と制御文字は使えません。

サンプル `n` は `<name>.in` と `<name>.out` として書き込まれるため、既定値は `sample-1.in`、`sample-1.out` のようになります。

### `handmade.filename`

| 型     | 既定値        | スコープ                     |
| ------ | ------------- | ---------------------------- |
| string | `handmade-{}` | グローバルまたはプロジェクト |

`neoj handmade` が作るテストケースのベース名。`testcase.filename` と同じ規則に従います。`{}` をちょうど1つ含み、そこが1始まりのケース番号に置き換わり、有効なファイル名であることが必要です。ケース `n` は `testcase.folder` の中に `<name>.in` と `<name>.out` として書き込まれます。

番号は、`.in` と `.out` の両方のファイルがまだ存在しない最小の番号です。そのため、新しいケースが既存のケースを置き換えることはありません。手作りのケースはダウンロード済みのサンプルと同じディレクトリに置かれ、`neoj download` がそのディレクトリを置き換えるとき削除されます。

### `generate.gen`

| 型     | 既定値 | スコープ                     |
| ------ | ------ | ---------------------------- |
| string | —      | グローバルまたはプロジェクト |

`neoj generate` が使うジェネレータのソースファイル。プロジェクトのルートからの相対パスです。ジェネレータは解法と同じようにビルドされ、言語が判別され、ケース番号を最初の引数として実行されます。標準出力が新しいケースの `.in` ファイルになります。

### `generate.naive`

| 型     | 既定値 | スコープ                     |
| ------ | ------ | ---------------------------- |
| string | —      | グローバルまたはプロジェクト |

`neoj generate` が使う素朴な解法のソースファイル。プロジェクトのルートからの相対パスです。標準入力で生成された入力を受け取り、標準出力がケースの `.out` ファイルになります。`neoj generate --input` が入力だけを作るときを除き、必須です。

### `generate.filename`

| 型     | 既定値      | スコープ                     |
| ------ | ----------- | ---------------------------- |
| string | `random-{}` | グローバルまたはプロジェクト |

`neoj generate` が作るテストケースのベース名。`testcase.filename` と同じ規則に従います。`{}` をちょうど1つ含み、そこが1始まりのケース番号に置き換わり、有効なファイル名であることが必要です。番号は、`.in` と `.out` の両方のファイルがまだ存在しない最小の番号です。そのため、生成されたケースが、入力だけのケースを含めて既存のケースを置き換えることはありません。

### `generate.count`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| integer | `1`    | グローバルまたはプロジェクト |

`neoj generate` が1回の実行で作るテストケースの数。`--count` が上書きします。

### `generate.timeout`

| 型     | 既定値 | スコープ                     |
| ------ | ------ | ---------------------------- |
| number | `10`   | グローバルまたはプロジェクト |

ジェネレータと素朴な解法のそれぞれの実行に対する秒単位の時間制限。超えたツールは実行を止めます。

### `generate.parallel`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

テストケースを並列に生成します。`--no-parallel` は1つずつ実行します。

### `download.show_sample`

| 型      | 既定値  | スコープ                     |
| ------- | ------- | ---------------------------- |
| boolean | `false` | グローバルまたはプロジェクト |

ファイルの書き込みが成功したあと、ダウンロードしたすべてのサンプルの入力と出力を表示します。`false` のとき、`download` はサンプルの数とコピー先のディレクトリだけを報告します。

### `test.source`

| 型          | 既定値 | スコープ                     |
| ----------- | ------ | ---------------------------- |
| string path | なし   | グローバルまたはプロジェクト |

コマンドラインでソースが渡されないときに、`neoj test` がビルドするソースファイル。プロジェクトのルートから解決され、実在する単純なパスである必要があります。グロブは拒否されます。`neoj test <source>` が、1回の実行だけ上書きします。

### `test.interactor.source`

| 型          | 既定値 | スコープ                     |
| ----------- | ------ | ---------------------------- |
| string path | なし   | グローバルまたはプロジェクト |

`neoj test --interactive` が使うインタラクタのファイル。プロジェクトのルートから解決され、実在する単純なパスである必要があります。このセクションが読まれるのは `--interactive` が渡されたときだけのため、インタラクタのないプロジェクトもそのまま動きます。

```toml
[test.interactor]
source = "src/interactor.cpp"
run = ["{outfile}", "{infile}"]
```

### `test.interactor.compile`

| 型              | 既定値                             | スコープ                     |
| --------------- | ---------------------------------- | ---------------------------- |
| array of string | 一致する `languages.<key>.compile` | グローバルまたはプロジェクト |

インタラクタをビルドするコマンドと引数。省いたとき、`neoj` は `source` グロブがインタラクタのファイルに一致する `[languages.<key>]` を選び、その `compile` を再利用します。複数の言語が一致するときは、1つを選ぶために `compile` と `run` をここで設定します。コマンドは言語の `compile` と同じく、`{outfile}` か `{outdir}` を参照する必要があります。

### `test.interactor.run`

| 型              | 既定値                         | スコープ                     |
| --------------- | ------------------------------ | ---------------------------- |
| array of string | 一致する `languages.<key>.run` | グローバルまたはプロジェクト |

インタラクタを実行するコマンドと引数。[サンプルテストをビルドして実行する](../how-to/run-tests.md#プレースホルダー)に挙げたプレースホルダーに加えて、`{infile}` がテストケースの `.in` のパスに展開されます。`{infile}` は `compile` では使えません。パスがケースごとに変わるためです。

### `test.interactor.timeout`

| 型               | 既定値 | スコープ                     |
| ---------------- | ------ | ---------------------------- |
| number (seconds) | `15`   | グローバルまたはプロジェクト |

1つの対話セッションに対する実時間の制限。期限が切れると、解法とインタラクタの両方が停止され、ケースは `TLE` として報告されます。解法自身の `test.timeout` も引き続き適用され、それより早く止められます。

### `test.judge.source`

| 型          | 既定値 | スコープ                     |
| ----------- | ------ | ---------------------------- |
| string path | なし   | グローバルまたはプロジェクト |

`neoj test --judge` が使うチェッカーのファイル。プロジェクトのルートから解決され、実在する単純なパスである必要があります。このセクションが読まれるのは `--judge` が渡されたときだけのため、チェッカーのないプロジェクトもそのまま動きます。

```toml
[test.judge]
source = "src/checker.cpp"
run = ["{outfile}", "{infile}"]
```

### `test.judge.compile`

| 型              | 既定値                             | スコープ                     |
| --------------- | ---------------------------------- | ---------------------------- |
| array of string | 一致する `languages.<key>.compile` | グローバルまたはプロジェクト |

チェッカーをビルドするコマンドと引数。省いたとき、`neoj` は `source` グロブがチェッカーのファイルに一致する `[languages.<key>]` を選び、その `compile` を再利用します。複数の言語が一致するときは、1つを選ぶために `compile` と `run` をここで設定します。コマンドは言語の `compile` と同じく、`{outfile}` か `{outdir}` を参照する必要があります。

### `test.judge.run`

| 型              | 既定値                         | スコープ                     |
| --------------- | ------------------------------ | ---------------------------- |
| array of string | 一致する `languages.<key>.run` | グローバルまたはプロジェクト |

チェッカーを実行するコマンドと引数。解法の標準出力がチェッカーの標準入力に書き込まれます。[サンプルテストをビルドして実行する](../how-to/run-tests.md#プレースホルダー)に挙げたプレースホルダーに加えて、チェッカーが入力を必要とするとき、`{infile}` がテストケースの `.in` のパスに展開されます。`{infile}` は省略でき、`compile` では使えません。パスがケースごとに変わるためです。

### `test.judge.timeout`

| 型               | 既定値 | スコープ                     |
| ---------------- | ------ | ---------------------------- |
| number (seconds) | `10`   | グローバルまたはプロジェクト |

1回のチェッカーの実行に対する実時間の制限。期限が切れると、チェッカーが停止され、ケースは `TLE` として報告されます。解法自身の `test.timeout` は別に適用され、チェッカーが始まる前に解法を止められます。チェッカーにはメモリ制限がありません。

### `test.timeout`

| 型               | 既定値 | スコープ                     |
| ---------------- | ------ | ---------------------------- |
| number (seconds) | `10`   | グローバルまたはプロジェクト |

各テストケースに対する実時間の制限。プロセスの開始から終了までを測ります。小数も許されます。`languages.<key>.timeout` が言語ごとに上書きし、`--timeout` が両方を上書きします。

### `test.memory`

| 型               | 既定値 | スコープ                     |
| ---------------- | ------ | ---------------------------- |
| number (integer) | `1024` | グローバルまたはプロジェクト |

MiB単位のメモリ制限。制限は、プログラムが終了したあと、直接の子プロセスのピークの常駐メモリで確認されるため、実行中のプログラムは止められません。スクリプトが起動するインタプリタのような孫プロセスは数えません。

### `test.parallel`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

テストケースを並列に実行します。既定のジョブ数は、論理CPU数とケース数の小さい方です。`--jobs` と `--no-parallel` が上書きします。最終報告は、常に名前順でケースを並べます。

### `test.cache`

| 型      | 既定値  | スコープ                     |
| ------- | ------- | ---------------------------- |
| boolean | `false` | グローバルまたはプロジェクト |

コンパイル済みプログラムを `.neoj/build/<hash>/` の下に残し、同じソース、コマンド、追加の入力が変わらなければコンパイルを省きます。`false` のとき、実行のビルドディレクトリはそのあと削除されます。`--cache` と `--no-cache` が、1回の実行だけ上書きします。

### `test.error`

| 型                 | 既定値 | スコープ                     |
| ------------------ | ------ | ---------------------------- |
| integer (`0`–`15`) | `6`    | グローバルまたはプロジェクト |

`neoj test --error` が使う浮動小数点の許容差の指数。`-e` が許容差を有効にし、この値はオプションに引数がないときの既定です。`-e 9` が1回の実行だけ上書きします。比較は、`|actual - expected| <= 10^-error * max(1, |expected|)` のときにトークンを認めます。

### `test.ignore_trailing_space`

| 型      | 既定値  | スコープ                     |
| ------- | ------- | ---------------------------- |
| boolean | `false` | グローバルまたはプロジェクト |

比較のとき、各出力行の末尾の空白を無視します。行の中の空白は引き続き意味を持ちます。`-S` が、1回の実行だけ有効にします。

### `test.ignore_trailing_newline`

| 型      | 既定値  | スコープ                     |
| ------- | ------- | ---------------------------- |
| boolean | `false` | グローバルまたはプロジェクト |

比較のとき、出力の末尾の改行の欠けや余りを無視します。`-N` が、1回の実行だけ有効にします。

### `test.show_stderr`

| 型     | 既定値     | スコープ                     |
| ------ | ---------- | ---------------------------- |
| string | `"always"` | グローバルまたはプロジェクト |

実行後の報告に、プログラムの標準エラーを表示します。値は次のいずれかです。

- `"always"` — 合格したケースも含め、すべてのケースの標準エラーを表示します。
- `"failure"` — 合格しなかったケース(`WA`、`TLE`、`MLE`、`RE`、`UNJUDGED`)にだけ表示します。
- `"never"` — 決して表示しません。

行は取得したとおりに、色も行数の制限もなく、`stderr:` のラベルの下に表示されます。`--show-stderr <mode>` が、1回の実行だけ設定を上書きします。

### `test.display_lines`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| integer | `30`   | グローバルまたはプロジェクト |

報告で各ブロックに表示する行数。残りは `… N more line(s)` として要約されます。入力とプログラムの出力に適用されます。`WA` の比較は、差が見えるよう常にすべての行を並べます。`1` 以上であることが必要です。

### `test.show_line_numbers`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

報告の入力と出力の表の各行に、行番号を付けます。比較の表では、`Expected` と `Output` の横に、行ごとに1度ずつ番号が付きます。`--no-show-line-numbers` が1回の実行だけ無効にします。

### `run.silent`

| 型      | 既定値  | スコープ                     |
| ------- | ------- | ---------------------------- |
| boolean | `false` | グローバルまたはプロジェクト |

`neoj run` の情報としてのログを隠します。たとえば `Compiled src/main.cpp (languages.cpp) in 41 ms.` や、キャッシュの再利用の行です。コンパイラの診断とすべてのエラーメッセージは、引き続き標準エラーに表示されます。`--silent` が、1回の実行だけ有効にします。オプションはソースファイルより前に置く必要があり、`neoj run src/main.cpp --silent` の `--silent` は代わりにプログラムに渡ります。

同じログは、標準エラーがターミナルでないときにも自動で隠れるため、`neoj run > out.txt 2>&1` や、出力を取得するスクリプトは静かです。

### `submit.confirm`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

提出前に確認を求めます。プロンプトの既定は **No** です。`--yes` が、1回の実行だけプロンプトを飛ばします。待ち時間は保たれます。

### `submit.wait`

| 型               | 既定値 | スコープ                     |
| ---------------- | ------ | ---------------------------- |
| number (seconds) | `3`    | グローバルまたはプロジェクト |

確認のあと、プラットフォームに問い合わせるまでに待つ時間。最終確認が可能なままになります。ターミナルでは、コマンドが標準エラーにカウントダウンのバーを描きます。それ以外では1行を表示します。`--wait <seconds>` と `--no-wait` が1回の実行だけ上書きします。`--yes` は待ち時間を飛ばしません。

### `submit.open`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

提出が成功したあと、提出ページをブラウザで開きます。`--open` と `--no-open` が1回の実行だけ上書きします。ブラウザを起動できなくても警告が出るだけで、コマンドは成功します。

### `submit.clip`

| 型     | 既定値    | スコープ                     |
| ------ | --------- | ---------------------------- |
| string | `"never"` | グローバルまたはプロジェクト |

`neoj submit` が提出するテキストをクリップボードにコピーするかどうかです。

- `"never"` — 決してコピーしません。
- `"always"` — presubmit のコマンドのあとにコピーし、そのまま提出します。クリップボードが使えなくても警告が出るだけです。
- `"fail"` — 提出が失敗したときだけコピーします。ブラウザに貼り付けられるためです。この場合も、コマンドは `1` で終了します。

この設定にはコマンドラインのフラグがありません。

### `submit.preview_lines`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| integer | `5`    | グローバルまたはプロジェクト |

提出プレビューの最初と最後に表示する行数。実際の行番号が付き、2つのブロックの間は `...` です。`2 * preview_lines` 行以下のファイルは全体が表示されます。

### `submit.presubmit_timeout`

| 型               | 既定値 | スコープ                     |
| ---------------- | ------ | ---------------------------- |
| number (seconds) | `30`   | グローバルまたはプロジェクト |

`languages.<key>.presubmit` に対する実時間の制限。期限が切れると、neoj はコマンドを停止し、presubmit がタイムアウトしたと報告します。

### `languages.<key>.source`

| 型                    | 既定値 | スコープ                     |
| --------------------- | ------ | ---------------------------- |
| string or string list | 必須   | グローバルまたはプロジェクト |

この言語で書かれたファイルを識別する、プロジェクトのルートからのグロブ(またはグロブの一覧)。`neoj test` は解決したソースファイルをこれらのグロブに照合して言語を選ぶため、`--language` がない限り、ちょうど1つの言語が一致しなければなりません。絶対パスのパターンと `..` のセグメントは拒否されます。

### `languages.<key>.compile`

| 型              | 既定値 | スコープ                     |
| --------------- | ------ | ---------------------------- |
| list of strings | なし   | グローバルまたはプロジェクト |

ソースをビルドするコマンドと引数。`{outfile}` か `{outdir}` を参照する必要があります。インタプリタ言語では省きます。

### `languages.<key>.run`

| 型              | 既定値 | スコープ                     |
| --------------- | ------ | ---------------------------- |
| list of strings | 必須   | グローバルまたはプロジェクト |

ビルドしたプログラムを実行するコマンドと引数。標準入力でテスト入力を受け取ります。

### `languages.<key>.timeout`

| 型               | 既定値         | スコープ                     |
| ---------------- | -------------- | ---------------------------- |
| number (seconds) | `test.timeout` | グローバルまたはプロジェクト |

この言語の時間制限。

### `languages.<key>.memory`

| 型               | 既定値        | スコープ                     |
| ---------------- | ------------- | ---------------------------- |
| number (integer) | `test.memory` | グローバルまたはプロジェクト |

この言語のメモリ制限。MiB単位です。

### `languages.<key>.cache_files`

| 型                    | 既定値 | スコープ                     |
| --------------------- | ------ | ---------------------------- |
| string or string list | なし   | グローバルまたはプロジェクト |

共有ヘッダーのような、中身がコンパイルのキャッシュキーに含まれる追加のファイル。コンパイラには渡されず、変わったときにキャッシュを無効化するだけです。

### `languages.<key>.presubmit`

| 型              | 既定値 | スコープ                     |
| --------------- | ------ | ---------------------------- |
| list of strings | なし   | グローバルまたはプロジェクト |

ソースを、`neoj submit` が送るテキストに変えるコマンドと引数。プロジェクトのルートで実行され、環境に加えて `NEOJ_PLATFORM`、`NEOJ_PROBLEM_URL`、`NEOJ_LANGUAGE` を受け取ります。元のファイルが変更されることはありません。

| プレースホルダー | 値                                             |
| ---------------- | ---------------------------------------------- |
| `{source}`       | 元のソースファイルの絶対パス。                 |
| `{outfile}`      | ソースファイルの拡張子を保った一時の出力パス。 |
| `{outdir}`       | `{outfile}` などの一時出力を置くディレクトリ。 |
| `{dir}`          | プロジェクトのルート。                         |

提出するテキストを `{outfile}` に書き込みます。コマンドが `{outfile}` を参照しないときは、代わりに標準出力が提出されます。どちらの場合でも、空の結果はエラーです。`--no-presubmit` が、1回の実行だけコマンドを飛ばします。

```toml
[languages.cpp]
source = "src/**/*.cpp"
compile = ["g++", "-std=c++23", "-O2", "-o", "{outfile}", "{source}"]
run = ["{outfile}"]
presubmit = ["python", "tools/expand.py", "{source}", "{outfile}"]
submit = { atcoder = "5001", yukicoder = "5001" }
```

### `languages.<key>.submit`

| 型                     | 既定値 | スコープ                     |
| ---------------------- | ------ | ---------------------------- |
| table of string values | なし   | グローバルまたはプロジェクト |

この言語のプラットフォームの言語ID。キーはプラットフォーム名です。`neoj submit` はAtCoderに `submit.atcoder` を、yukicoderに `submit.yukicoder` を使います。`--platform-language <id>` が、1回の実行だけ上書きします。キーがないときは、コマンドがそのプラットフォームの使えるIDを一覧表示し、確認を求める代わりに `1` で終了します。

### `compile` と `run` のプレースホルダー

| プレースホルダー | 値                                               |
| ---------------- | ------------------------------------------------ |
| `{source}`       | ソースファイルの絶対パス。                       |
| `{outfile}`      | ビルドされたプログラムの絶対パス。拡張子なし。   |
| `{outdir}`       | `{outfile}` などのビルド出力を置くディレクトリ。 |
| `{dir}`          | プロジェクトのルート。                           |
| `{testdir}`      | テストケースディレクトリの絶対パス。             |

プレースホルダーは各引数の中で置き換えられます。未知のプレースホルダーは設定のエラーです。Windowsでは、存在しない `{outfile}` が、`{outfile}.exe` というファイルが存在するときそのパスに置き換わります。拡張子をコンパイラ自身が付けることがあるためです。

### `stash.auto_stash`

| 型      | 既定値  | スコープ                     |
| ------- | ------- | ---------------------------- |
| boolean | `false` | グローバルまたはプロジェクト |

`download` がテストケースのディレクトリを置き換える前に、現在の問題の作業ファイルを保存します。`neoj` が退避を書き込むのは、ダウンロードした問題が `.neoj/problem.json` のURLと異なるときだけです。スナップショットには、設定されていれば `src` と、`testcase.folder` が入ります。

### `stash.auto_apply`

| 型      | 既定値  | スコープ                     |
| ------- | ------- | ---------------------------- |
| boolean | `false` | グローバルまたはプロジェクト |

問題が変わるダウンロードのあと、新しい問題の退避が存在すれば復元します。退避は保たれるため、別の問題をダウンロードして戻ってくると、もう一度復元します。

### `stash.force`

| 型      | 既定値 | スコープ                     |
| ------- | ------ | ---------------------------- |
| boolean | `true` | グローバルまたはプロジェクト |

`neoj stash save` が、同じ問題の既存の退避を置き換えることを許します。`false` のときは、`--force` を渡すまで `save` が失敗します。`stash.auto_stash` は常に退避を更新し、`neoj stash clear` は常に `--force` を必要とします。

### `template.enable`

| 型      | 既定値  | スコープ     |
| ------- | ------- | ------------ |
| boolean | `false` | プロジェクト |

問題が変わるダウンロードのあと、テンプレートを `src` に適用します。有効にするには `src` と `template.folder` の両方が必要です。同じ問題をもう一度ダウンロードしても、サンプルは更新されますが、テンプレートは再適用されません。

### `template.folder`

| 型          | 既定値 | スコープ     |
| ----------- | ------ | ------------ |
| string path | なし   | プロジェクト |

テンプレートのファイルを置くディレクトリ。プロジェクトのルートから解決されます。`template.enable = true` のときに存在する必要があり、空のディレクトリも許されます。パスはプロジェクトの中に留まること、`.git` と `.neoj` を指さないこと、`src` と重ならないことが必要で、木の中にシンボリックリンクがあってはいけません。隠しファイルも、他のファイルと同じようにコピーされます。

### `template.exclude`

| 型            | 既定値 | スコープ     |
| ------------- | ------ | ------------ |
| array of glob | `[]`   | プロジェクト |

`template.folder` の中の、`src` にコピーしてはいけないファイルのグロブ。パターンは、`template.folder` からの相対パスと、エントリ名の両方に照らして一致するため、`*.md` はサブディレクトリの中のMarkdownファイルも除外します。一致したディレクトリは中身ごと飛ばされます。パターンが入れ子のパスだけに一致してほしいときは、`**/` を明示的に使います。

### `template.mode`

| 型                     | 既定値    | スコープ     |
| ---------------------- | --------- | ------------ |
| `overlay` or `replace` | `overlay` | プロジェクト |

テンプレートを `src` に適用する方法です。

- `overlay` は、テンプレートを `src` の上にコピーします。両方にあるファイルを置き換え、それ以外を保ちます。
- `replace` は、テンプレートをコピーする前に `src` の中身を削除します。

```toml
src = "src"

[alias]

parallel = true
cache = false
```

## 検証のエラー

結合した設定が検証を通らなかったとき、`neoj` は読んだファイルのパスを報告したうえで、それぞれの無効なキーを、理由と受け取った値の型とともに報告します。値そのものは表示されません。
