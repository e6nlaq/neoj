# CLIリファレンス

## コマンド

| コマンド                                                     | 説明                                                                                                     |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `neoj init [--force]`                                        | 同梱のテンプレートを現在のプロジェクトにコピーします。                                                   |
| `neoj download <url>`(エイリアス: `neoj d`)                  | 問題のサンプルテストをテストケースディレクトリにダウンロードします。                                     |
| `neoj open [options]`(エイリアス: `neoj o`)                  | 現在の問題をブラウザで開きます。                                                                         |
| `neoj handmade`(エイリアス: `neoj h`)                        | 対話入力から手作りのテストケースを作ります。                                                             |
| `neoj generate`(エイリアス: `neoj g`)                        | ジェネレータと素朴な解法でランダムテストケースを作ります。                                               |
| `neoj login <platform>`                                      | プラットフォームにログインします。対応している名前は `atcoder` と `yukicoder` です。                     |
| `neoj logout [--service <name...>]`                          | 指定したプラットフォームからログアウトします。名前を省くとすべてのプラットフォームからログアウトします。 |
| `neoj status [--offline]`                                    | 対応しているすべてのプラットフォームのログイン状態を表示します。                                         |
| `neoj stash [save\|list\|apply\|pop\|drop\|clear]`           | 現在の問題の作業ファイルを保存・復元します。                                                             |
| `neoj test [source]`(エイリアス: `neoj t`)                   | 解法をビルドし、サンプルテストで実行します。                                                             |
| `neoj run [source] [args...]`(エイリアス: `neoj r`)          | 解法をビルドし、テストなしで実行します。`args` はそのまま渡ります。                                      |
| `neoj submit [source]`(エイリアス: `neoj s`、`neoj submits`) | 現在の問題に解法を提出します。                                                                           |
| `neoj languages [platform]`(エイリアス: `neoj langs`)        | プラットフォームが受け付ける言語IDを一覧表示します。                                                     |
| `neoj prune [--dry-run]`                                     | `.neoj/build/` の下のキャッシュ済みビルドをすべて削除します。                                            |
| `neoj completions <shell>`(エイリアス: `neoj completion`)    | bash、zsh、fish、PowerShell 向けの補完スクリプトを表示します。                                           |

### `init`

| オプション      | 説明                           |
| --------------- | ------------------------------ |
| `-f`, `--force` | 既存のファイルを上書きします。 |

最も近い `neoj.toml` があるディレクトリに書き込みます。見つからないときは現在のディレクトリです。探索はリポジトリのルートで止まります。

### `download`

| 引数    | 説明                              |
| ------- | --------------------------------- |
| `<url>` | AtCoderまたはyukicoderの問題URL。 |

初期化済みのプロジェクトが必要です。[サンプルテストをダウンロードする](../how-to/download-samples.md)を参照してください。

### `open`

最後の成功したダウンロードが記録した問題のページを開きます。そのため、先に `neoj download <url>` を実行します。

| オプション            | 説明                                              |
| --------------------- | ------------------------------------------------- |
| `-c`, `--contest`     | 現在の問題の競技ページを開きます。                |
| `-s`, `--submissions` | 現在の問題の自分の提出を開きます。                |
| `--clip`              | 開く代わりに、URLをクリップボードにコピーします。 |
| `--url`               | 開く代わりに、URLを表示します。                   |

`--contest` と `--submissions`、そして `--clip` と `--url` は、それぞれ併用できません。

| 対象            | AtCoder                                                                  | yukicoder                                                                                                                       |
| --------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| (既定)          | 問題ページ。                                                             | 問題ページ。                                                                                                                    |
| `--contest`     | `https://atcoder.jp/contests/<contestId>`                                | 問題が属する競技。公開APIを通じて解決します。                                                                                   |
| `--submissions` | `https://atcoder.jp/contests/<contestId>/submissions/me?f.Task=<taskId>` | 問題自体の提出ページ(`/problems/no/<n>/submissions` または `/problems/<id>/submissions`)に `my_submission=enabled` を付けたもの |

AtCoderのURLは問題URLから導かれます。yukicoderは競技を問題URLに記録しないため、`--contest` は公開APIに問い合わせます。ネットワークアクセスが必要で、どの競技にも属さない問題はこの方法で開けません。1つの問題が複数の競技に現れるとき、APIはそのうちの1つだけを報告します。

ブラウザを起動できないときは、URLが表示されるため手で開けます。コマンドは `1` で終了します。

`--url` はURLだけを標準出力に表示するため、スクリプトから使えます。`--clip` はURLをコピーし、結果を表示します。クリップボードが使えないときは、URLを標準エラーに報告し、`1` で終了します。

### `handmade`

ターミナルからテストケースを1つ読み、テストケースディレクトリに書き込みます。

```text
$ neoj handmade
test/handmade-1.in and test/handmade-1.out will be created.
input> 1 2
input>

output> 3
output>
✔ Created test/handmade-1.in and test/handmade-1.out.
```

入力を1行ずつ打ち、空行でブロックを終えます。続いて期待する出力も同じように打ちます。空行が2つのブロックを分けます。両方のファイルが書き込まれるのは、出力のブロックが閉じたあとです。そのため、中断したセッションがファイルを残しません。Ctrl-C または Ctrl-D(Windowsでは Ctrl-Z)は、書き込まずにコマンドを中断します。

コマンドは空いている次のケース番号を使うため、既存のケースを置き換えません。ディレクトリは `testcase.folder` から、ファイル名は `handmade.filename`(既定は `handmade-{}`)から決まります。対話的なターミナルと初期化済みのプロジェクトが必要です。[テストケースを手で作る](../how-to/create-handmade-tests.md)を参照してください。

`neoj download` はテストケースのディレクトリ全体を置き換えるため、そこに置いた手作りのファイルは次のダウンロードで削除されます。ディレクトリは `src` や `.neoj` であってはならず、`src` を含んだり `src` の中に置かれたりしてはいけません。

### `generate`

2つのプログラムを組み合わせてランダムテストケースを作ります。`generate.gen` のジェネレータがテストケースの入力を出力し、`generate.naive` の素朴な解法がその入力から期待する出力を作ります。どちらも解法と同じ形式でビルドされ、言語は `[languages.<key>]` から判別されます。

```text
$ neoj generate
✔ Compiled judge/gen.ts (generate.gen) in 0.12 s.
✔ Compiled judge/naive.ts (generate.naive) in 0.10 s.
✔ Created 2 test case(s): random-1, random-2.
```

ジェネレータはケース番号を最初の引数として実行されるため、失敗したケースを再現できます。`random-7` は `judge/gen.cpp 7` から生まれたものです。ジェネレータの標準入力はすぐに閉じられ、標準出力が `.in` ファイルになり、素朴な解法の標準入力にパイプされます。その解法の標準出力が `.out` ファイルになります。空の入力と出力はそのまま書き込まれ、それ以外にプログラムの出力が整形されることはありません。

ケースは空いている次の番号でテストケースディレクトリに書き込まれるため、既存のケースを置き換えません。ファイルが書き込まれるのは、ケースの両方の部分が完成したあとです。Ctrl-C は実行中のプログラムを止め、途中まで書かれたケースを削除します。0以外の終了状態で終わるツール、`generate.timeout` 秒後のタイムアウト、出力の上限をあふれさせるツールは、実行全体を止めます。失敗前に完成したケースはディスクに残ります。

| オプション                     | 説明                                                              |
| ------------------------------ | ----------------------------------------------------------------- |
| `-i`, `--input`                | `.in` ファイルだけを作ります。`generate.naive` は不要です。       |
| `-c`, `--count <count>`        | 作るケース数(既定: `generate.count`)。                            |
| `-J`, `--jobs <count>`         | 一度に生成するケース数。                                          |
| `--no-parallel`                | 1つずつ生成します。                                               |
| `--cache` / `--no-cache`       | `.neoj/build/` の下のコンパイル済みプログラムを残すか削除します。 |
| `--progress` / `--no-progress` | 進捗バーを描くか隠します。                                        |

[ランダムテストケースを生成する](../how-to/generate-random-tests.md)を参照してください。

### `stash`

| サブコマンド | 説明                                                            |
| ------------ | --------------------------------------------------------------- |
| `save`(既定) | `src` とテストケースディレクトリを保存します。                  |
| `list`       | 保存済みの退避を一覧表示します。現在の問題には `*` を付けます。 |
| `apply`      | 現在の問題の退避を復元します。                                  |
| `pop`        | 現在の問題の退避を復元し、削除します。                          |
| `drop`       | 現在の問題の退避を削除します。                                  |
| `clear`      | すべての退避を削除します。                                      |

サブコマンドのない `neoj stash` は、`neoj stash save` と同じです。

| オプション      | コマンド | 説明                                     |
| --------------- | -------- | ---------------------------------------- |
| `-f`, `--force` | `save`   | 既存の退避を置き換えます。               |
| `-f`, `--force` | `clear`  | 必須。保存済みの退避をすべて削除します。 |

`list` と `clear` 以外のサブコマンドは、`.neoj/problem.json` に記録された問題に対して動きます。そのため、先に `neoj download <url>` を実行します。`apply` は保存されたファイルを復元し、保存されたディレクトリの中のその他のファイルを削除します。そのため、ディレクトリが退避と完全に一致します。[作業を問題ごとに退避・復元する](../how-to/stash-work.md)を参照してください。

### `test`

| 引数       | 説明                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| `[source]` | テストするソースファイル。`[alias]` の名前も受け付けます。既定は `test.source`。 |

テストケースディレクトリのすべての `*.in` ファイルを、ビルドしたプログラムで実行します。`--interactive` を付けると、`[test.interactor]` が指すインタラクタが各ケースを判定し、出力を `*.out` と比べなくなります。`--judge` を付けると、`[test.judge]` が指すチェッカーが解法の出力を受け取り、判定を決めます。

| オプション                                       | 説明                                                                  |
| ------------------------------------------------ | --------------------------------------------------------------------- |
| `-l`, `--language <key>`                         | 判別の代わりに、この `[languages.<key>]` のエントリを使います。       |
| `-J`, `--jobs <count>`                           | 一度に実行するテストケース数。                                        |
| `--no-parallel`                                  | テストケースを1つずつ実行します。                                     |
| `-t`, `--timeout <seconds>`                      | テストケースごとの時間制限。                                          |
| `-m`, `--memory <MiB>`                           | テストケースごとのメモリ制限。                                        |
| `-f`, `--filter <name...>`                       | 指定した名前のケースだけを実行します(`sample-1.in` なら `sample-1`)。 |
| `-i`, `--interactive`                            | `[test.interactor]` のインタラクタで判定します。                      |
| `-j`, `--judge`                                  | `[test.judge]` のチェッカーで判定します。                             |
| `-e`, `--error [exponent]`                       | `10^-exponent` までの浮動小数点の誤差を認めます。                     |
| `--cache` / `--no-cache`                         | `.neoj/build/` の下のコンパイル済みプログラムを残すか削除します。     |
| `-S`, `--ignore-trailing-space`                  | 各行の行末の空白を無視します。                                        |
| `-N`, `--ignore-trailing-newline`                | 出力の末尾の改行を無視します。                                        |
| `--show-stderr <mode>`                           | プログラムのstderrを表示します。`always`、`failure`、`never`。        |
| `--progress` / `--no-progress`                   | 進捗バーを描くか隠します。                                            |
| `--show-line-numbers` / `--no-show-line-numbers` | 入力と出力の表の行に番号を付けます。                                  |
| `-v`, `--verbose`                                | 合格したケースにも入力と出力を表示します。                            |

[サンプルテストをビルドして実行する](../how-to/run-tests.md)を参照してください。

### `run`

| 引数        | 説明                                                                           |
| ----------- | ------------------------------------------------------------------------------ |
| `[source]`  | 実行するソースファイル。`[alias]` の名前も受け付けます。既定は `test.source`。 |
| `[args...]` | プログラムにそのまま渡す引数。                                                 |

ソースをビルドし、ターミナルを接続したまま実行します。標準入力、出力、エラーはプログラムのものになり、時間制限もメモリ制限も出力の上限も掛かりません。テストケースディレクトリは読まないため、`test/` がなくても `neoj run` は動きます。

| オプション               | 説明                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| `-l`, `--language <key>` | 判別の代わりに、この `[languages.<key>]` のエントリを使います。   |
| `--cache` / `--no-cache` | `.neoj/build/` の下のコンパイル済みプログラムを残すか削除します。 |
| `--silent`               | `Compiled ... in N ms.` のような情報としてのログを隠します。      |

ソースより後ろはすべてプログラムに渡るため、neoj のオプションは先に置きます。ソースの前に置いた `--` は `test.source` を保ち、その後ろをすべて渡します。

```bash
neoj run src/main.cpp -x 1       # -x 1 goes to the program
neoj run -l cpp -- -x 1          # test.source + -x 1
neoj run --silent src/main.cpp   # neoj parses --silent
neoj run src/main.cpp --silent   # --silent goes to the program
```

`--silent` が隠すのは情報としてのログだけです。コンパイラ自身の診断とすべてのエラーメッセージは、引き続き標準エラーに表示されます。情報としてのログは、標準エラーがターミナルでないときにも自動で隠れるため、パイプやリダイレクトの出力はきれいなままです。[テストなしで解法を実行する](../how-to/run-a-solution.md)を参照してください。

### `submit`

| 引数       | 説明                                                                           |
| ---------- | ------------------------------------------------------------------------------ |
| `[source]` | 提出するソースファイル。`[alias]` の名前も受け付けます。既定は `test.source`。 |

`.neoj/problem.json` に記録された問題に解法を提出します。そのため、先に `neoj download <url>` を実行します。ソースの解決は `neoj test` と同じです。`[alias]` の名前、パス、`test.source` のいずれかで、`-l`、`--language <key>` が一致する複数の `[languages.<key>]` から選びます。提出前にファイルがコンパイルされることはありません。

| オプション                       | 説明                                                            |
| -------------------------------- | --------------------------------------------------------------- |
| `-l`, `--language <key>`         | 判別の代わりに、この `[languages.<key>]` のエントリを使います。 |
| `-p`, `--platform-language <id>` | このプラットフォームの言語IDで提出します。                      |
| `--yes`                          | 確認のプロンプトを飛ばします。待ち時間は流れます。              |
| `--wait <seconds>`               | 1回の実行で `submit.wait` を上書きします。                      |
| `--no-wait`                      | `--wait 0` を指定したのと同じように、すぐに提出します。         |
| `--no-presubmit`                 | `presubmit` を実行せずにソースファイルを提出します。            |
| `--dry-run`                      | プラットフォームに触れずにプレビューを表示します。              |
| `--open` / `--no-open`           | そのあと提出ページを開くか、開かないか。                        |

コマンドは次の手順をこの順で実行します。言語の `presubmit` コマンド、プレビュー、確認のプロンプト(既定は **No**)、待ち時間、提出。

プレビューは、最初と最後の `submit.preview_lines` 行を実際の行番号付きで表示し、間を `...` でつなぎます。`2 * preview_lines` 行以下のファイルは全体が表示されます。行番号は、標準出力がターミナルで `NO_COLOR` が設定されていないときに、`neoj test` と同じように薄く表示されます。`--yes` と `--dry-run` のときもプレビューと大きさが表示されるため、スクリプトから送られる内容を確かめられます。

提出の前に、`neoj` は設定されていれば `languages.<key>.presubmit` をプロジェクトのルートで実行します。`{source}` は元のファイルの絶対パス、`{outfile}` はソースの拡張子を保った一時ファイルです。提出するテキストをそこに書き込むか、コマンドが `{outfile}` を使わないときは標準出力に出します。元のファイルが変更されることはなく、一時ディレクトリはそのあと削除されます。失敗したコマンドは標準エラーを報告し、`1` で終了します。空の結果も同じです。既定の時間制限は `submit.presubmit_timeout`(30秒)です。

有効なプラットフォームのセッションがないとき、`login.auto_login` が `true`(既定)であれば、`neoj submit` はログインの流れを始めます。ログインを中断すると `0` で終わり、失敗すると `1` で終わります。プラットフォームの言語IDは `--platform-language` から、続いて `languages.<key>.submit.<platform>` から決まります。どちらも設定されていないときは、コマンドは使える言語IDを一覧表示し、確認を求める代わりに `1` で終了します。

提出が成功すると、コマンドは提出IDとURLを表示し、`--no-open` や `submit.open = false` がなければ、提出ページをブラウザで開きます。ブラウザを起動できなくても警告が出るだけで、コマンドは `0` で終了します。`submit.clip` は提出したテキストをクリップボードにコピーします。`"never"`(既定)、`"always"`(提出前にコピーし、引き続き提出する)、`"fail"`(提出が失敗したときだけコピーする。この場合も `1` で終了します)。

`--dry-run` はネットワーク要求、ログイン、言語IDの照会、クリップボードへのコピーを行いません。presubmit のコマンドを実行し、プレビューと大きさを表示します。`--platform-language` とは併用できず、`--wait`、`--no-wait`、`--open`、`--no-open`、`--yes` を無視します。

提出の自動化はプラットフォームに依存します。AtCoderは、Daily Trainingの競技(`adt_...`)、`neoj download` が記録した競技の開催時間の外、提出ページにTurnstileのチャレンジが含まれるときに警告を表示します。AtCoderが要求を拒否したとき、エラーは提出ページをブラウザで開くように促します。yukicoderの提出は、ウェブフォームと同じAPIを使います。[解法を提出する](../how-to/submit-solution.md)を参照してください。

### `languages`

| 引数         | 説明                                                             |
| ------------ | ---------------------------------------------------------------- |
| `[platform]` | プラットフォーム名。`atcoder` か `yukicoder`。既定は現在の問題。 |

`--platform-language` と `languages.<key>.submit.<platform>` が受け付ける言語IDを表示します。表は各IDに言語名を添えて並べ、そのプラットフォームで設定済みのIDには `*` を付けます。締めの行は、それらのIDを設定する `neoj.toml` のキーを示すか、1つも設定されていないときは設定の方法を説明します。

| オプション        | 説明                                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| `--filter <text>` | このテキストに一致するID、名前、ランタイムの言語だけを表示します。大文字小文字は区別しません。 |

`[platform]` を省くと、`.neoj/problem.json` に記録されたプラットフォームが使われます。問題が記録されていないときは、コマンドが代わりにプラットフォームを尋ねます。`yukicoder` はログイン不要です。`atcoder` はセッションが必要で、`login.auto_login` に従います。ログインを中断すると `0` で終わり、失敗すると `1` で終わります。AtCoderの問題が記録されていないとき、コマンドは競技 `abc100` に問い合わせ、見出しで代替として示します。言語の一覧はどの競技でも同じためです。

IDの使い方は[解法を提出する](../how-to/submit-solution.md)にあります。

### `prune`

`.neoj/build/` の下のキャッシュ済みビルドをすべて削除するため、次の `neoj test` や `neoj run` はゼロからコンパイルします。最も近い初期化済みプロジェクトが使われ、`.neoj/problem.json`、保存済みの退避、テストケースディレクトリはそのまま残ります。

| オプション  | 説明                                             |
| ----------- | ------------------------------------------------ |
| `--dry-run` | 削除せずに、キャッシュ済みのビルドを報告します。 |

コマンドはキャッシュ済みビルドの件数と合計の大きさを報告します。キャッシュは作り直せるため、確認なしに実行され、削除するものがなければ `No cached builds.` で成功します。

### `completions`

| 引数      | 説明                                                        |
| --------- | ----------------------------------------------------------- |
| `<shell>` | 補完を生成するシェル。`bash`、`zsh`、`fish`、`powershell`。 |

スクリプトを標準出力に書き込みます。インストールの例は[シェル補完を設定する](../how-to/setup-completions.md)にあります。PowerShell の補完には `pwsh` 7.2以降が必要です。

## 終了ステータス

`neoj` は、成功したコマンドのあとに `0` で、エラーを報告したコマンドは `1` で終わります。読めないテンプレートファイルのような部分的な失敗も `1` を返します。`neoj handmade` は、両方のブロックが完成する前に中断されたとき `1` を返します。

`neoj generate` は、設定、コンパイル、ツールの失敗で `1` を返し、Ctrl-C で中断されたときは `130` を返します。中断前に完成したケースはディスクに残ります。

`neoj test` は3つの値を使い分けます。すべてのケースが合格すると `0`、コンパイル、設定、環境のエラーでは `1`、1つでもケースが失敗すると(`WA`、`TLE`、`MLE`、`RE`)`2` です。期待する出力のないケースは `UNJUDGED` として報告され、終了ステータスに影響しません。

`neoj run` はプログラム自身の終了コードで終わります。設定、コンパイル、起動のエラーは `1` を返します。シグナルで終了させられたプログラムも、1行の知らせ(`--silent` で隠れます)のあとに `1` を返します。

`neoj submit` は、提出が成功したときと、確認やログインが中断されたときに `0` で終わります。設定、presubmit、ネットワーク、プラットフォームのエラーは `1` を返します。

`neoj languages` は、一覧を表示したあとと、ログインが中断されたときに `0` で終わります。対応していないプラットフォーム、プラットフォームを指定しないときの問題の不在、ネットワークや認証のエラーは `1` を返します。
